# Resume

A resume is read in 30 seconds, not 20 minutes. Cut the cruft. Get to the point.

## Operating principles

Apply these when writing or reviewing. Each maps to a real signal recruiters and hiring managers use.

1. **One page.** If more is needed, link out to a personal site. A job does not need 10+ bullets.
2. **Personal website beats almost anything.** A site with intentionality behind it puts the candidate above 90% of the pile. Suggest building one if absent.
3. **Curate every linked profile.** Linking X means the X is on display — same for any social. Old posts get read.
4. **Link GitHub. Keep the profile clean.** No MySpace-style README full of badges, GIFs, and trophy widgets. The code and the projects should speak.
5. **Customize per company.** Startups care about shipping and ownership; old college coursework rarely matters there. Big-company ATS pipelines (FAANG-style) are the place where keywords and credentials still pull weight.
6. **Show AI fluency.** Software engineering is changing. Resumes that ignore AI, agents, or AI-assisted coding stand out in a bad way. Reflect it in projects, tools used, and bullet points.
7. **LinkedIn matters even if X is where the dev community lives.** Internal sharing inside companies happens on LinkedIn. Treat it as a real surface, not a graveyard.
8. **Show taste and personality.** Books, writing, films, side interests — anything that signals a thoughtful, well-rounded person and gives an interviewer a conversation starter. People hire people they want to work with.
9. **Do not let an LLM write the prose.** It is obvious, especially to AI companies. Use AI to brainstorm phrasing or pressure-test bullets, but the words on the page should be the candidate's own. Avoid the well-worn AI register ("leveraged," "spearheaded," "in today's fast-paced," "delve," em-dash-heavy cadence). If a humanizer skill is available, use it.
10. **No photos on the resume.** Save those for linked sites or LinkedIn.
11. **Quality over quantity.** Three thoughtful, detailed projects beat 27 AI-slop ones. If a project cannot be described in a sentence with a real outcome, cut it.

## Workflow: reviewing a resume

1. **Length check.** More than one page → flag immediately and identify what to cut.
2. **Top-of-page check.** Name, contact, links (GitHub, personal site, LinkedIn). Anything broken, missing, or unprofessional is the first fix.
3. **Link audit.** Open or ask about each link. Anything linked is part of the application. Wild X feed, badge-stuffed GitHub README, abandoned LinkedIn → flag.
4. **Bullet audit.** For each bullet ask: is there a concrete outcome (number, scope, user impact)? Is it written in the candidate's voice or in AI-register? Are there 10+ bullets per role? Cut to the strongest 3–5.
5. **AI signal.** If the resume has zero mention of AI tools, agents, or AI-assisted work, surface this — most engineering roles in 2026 assume some fluency.
6. **Customization fit.** Ask which company/role this is for. Adjust emphasis: startup → shipped projects, ownership, scrappy wins; large company → ATS keywords, credentials, scale.
7. **Personality surface.** Is there anywhere a real human shows up — a side project, reading list, writing? If not, suggest one tasteful place to add it (often a personal site link).
8. **Project quality pass.** Force-rank projects. Keep the top 3. Each should answer: what did you build, why was it interesting, what was the outcome.
9. **Photo / cruft check.** Remove photos, "References available on request," objective statements, skill bars, and decorative graphics.

## Workflow: writing from scratch

1. Ask for: target role, target company (or type — startup vs FAANG vs scaleup), current experience, links the person already has, and a couple of projects they are proud of.
2. Draft one page. Sections in order: name + links, experience, projects, education, (optional) interests/writing.
3. Each role: 3–5 bullets, outcome-led, candidate's own words.
4. Each project: one line of what + one line of outcome or technical interest. Link to the repo or live site.
5. Skim for AI-register phrasing. Rewrite anything that sounds like a model wrote it.
6. Confirm: does anything here show taste, judgment, or a point of view? If not, add one element that does.

## Cover letters

Same rule as resumes: the human writes the prose. AI is fine for ideation and gut-checks, never for final text. A cover letter that reads like ChatGPT to an AI company is an instant signal of either laziness or low taste. Short, specific, and personal beats long and polished every time.

## What to push back on

- Requests to "make it sound more professional" that really mean "make it sound more like an LLM." Resist.
- Padding to fill a second page. The second page is almost always worse than no second page.
- Stuffing every keyword imaginable. ATS gaming has limits and human readers see through it.
- Listing every technology ever touched. A skills wall of 60 items signals nothing.

## Quick heuristics

- If a bullet could appear on anyone's resume, rewrite it or cut it.
- If a project sounds like it took an afternoon with an AI assistant, do not list it as a flagship.
- If the resume is silent on what the candidate is actually interested in, the application is replaceable.
- One page. Real links. Real projects. Real voice.
