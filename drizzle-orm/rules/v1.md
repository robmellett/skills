# Migrating 0.4x → v1

```bash
pnpm add drizzle-orm@beta drizzle-kit@beta   # while v1 is unreleased; drop @beta once it ships
```

The migration is mostly mechanical: rewrite the relations file, swap `schema` for `relations` in `drizzle()`, and convert `db.query` `where` callbacks to the new filter syntax. Table definitions, selects, and writes are unchanged.

## Relations Move to One File

Per-table `relations()` is replaced by a single `defineRelations()` over the whole schema:

```ts
// relations.ts
import { defineRelations } from 'drizzle-orm';
import * as schema from './schema';

export const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.many.posts({ from: r.users.id, to: r.posts.authorId }),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      optional: false,     // makes `author` non-nullable in the result type
    }),
  },
}));
```

```ts
const db = drizzle(client, { relations });   // `relations`, not `schema`
```

Three things this buys, each of which retires an 0.4x workaround:

- **Declare one direction.** v1 no longer forces both sides.
- **`optional: false`** makes a required `one` relation non-nullable in the type, instead of every parent lookup returning a maybe.
- **A predefined `where`** on a relation — filtered and polymorphic relations without repeating the filter at every call site.

## Many-to-Many Collapses

`.through()` removes the junction hop from queries entirely:

```ts
groups: r.many.groups({
  from: r.users.id.through(r.usersToGroups.userId),
  to: r.groups.id.through(r.usersToGroups.groupId),
}),
```

Queries become `with: { groups: true }` — no `columns: {}`, no nested `usersToGroups`. Flattening code written for the 0.4x shape ([`relations.md`](relations.md)) should be deleted, not ported.

## Other Changes

- **`casing`** — `drizzle({ casing: 'camelCase' })` is gone. Use entity-level helpers: `import { snakeCase } from 'drizzle-orm/pg-core'`, then `snakeCase.table(...)`.
- **MySQL `mode: 'planetscale' | 'default'`** is gone — one strategy for all MySQL dialects.
- **`DrizzleQueryError`** wraps driver errors with the query and params attached. Catch it instead of pattern-matching driver error strings.
- **Legacy types** moved to `drizzle-orm/_relations`. Importing from there is a migration crutch, not a destination.

## Order of Work

1. Upgrade both `drizzle-orm` and `drizzle-kit` together.
2. Write `relations.ts`; delete the per-table `relations()` exports.
3. Change `drizzle(client, { schema })` → `drizzle(client, { relations })` at every construction site — including tests and any D1 per-request factory ([`d1-workers.md`](d1-workers.md)).
4. Fix `db.query` call sites the compiler flags — mostly `where` callbacks.
5. Collapse many-to-many traversals onto `.through()` and delete the flattening code.
6. Run `drizzle-kit generate` and confirm the diff is **empty** — a v1 upgrade should not change the database. A non-empty diff means a `casing` or naming regression, not a real schema change.
